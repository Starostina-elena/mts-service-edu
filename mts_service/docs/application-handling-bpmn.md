# Бизнес-процесс: обработка заявки

Исполняемое описание BPMN 2.0:

`src/main/resources/bpmn/application-handling.bpmn`

Диаграмма:

`docs/diagrams/application-handling-bpmn.svg`

## Последовательность процесса

1. Пользователь отправляет заявку.
2. Camunda запускает процесс `applicationHandling`.
3. Сервисная задача создаёт запись заявки со статусом `PENDING`.
4. Асинхронная сервисная задача публикует событие `applications.created` в Kafka.
5. Менеджер получает пользовательскую задачу на принятие решения.
6. Пока задача менеджера ожидает выполнения, не прерывающий таймер периодически запускает уведомление менеджеров.
7. Менеджер одобряет или отклоняет заявку.
8. При одобрении списывается баланс пользователя, заявка переводится в `APPROVED`, вызывается адаптер Taiga.
9. При отклонении сохраняется причина, заявка переводится в `REJECTED`, вызывается адаптер Taiga.

## Элементы BPMN

| Элемент | BPMN id | Тип | Реализация |
| --- | --- | --- | --- |
| Заявка отправлена | `applicationSubmitted` | Стартовое событие | Camunda Form `application-create` |
| Создать заявку | `createApplication` | Сервисная задача | `${createApplicationDelegate}` |
| Опубликовать событие | `publishApplicationCreated` | Асинхронная сервисная задача | `${publishApplicationCreatedDelegate}` |
| Решение менеджера | `managerDecision` | Пользовательская задача | Candidate group `MANAGER`, Camunda Form `manager-decision` |
| Таймер ожидания | `pendingReminderTimer` | Граничное таймер-событие | `R/PT5M` |
| Уведомить менеджеров | `notifyManagers` | Сервисная задача | `${notifyManagersDelegate}` |
| Одобрено? | `approvalGateway` | Исключающий шлюз | `${approved == true}` / `${approved == false}` |
| Одобрить заявку | `approveApplication` | Сервисная задача | `${approveApplicationDelegate}` |
| Отклонить заявку | `rejectApplication` | Сервисная задача | `${rejectApplicationDelegate}` |
| Одобрено | `applicationApproved` | Конечное событие | Завершение процесса |
| Отклонено | `applicationRejected` | Конечное событие | Завершение процесса |

## Интеграция требований

| Требование | Интеграция в BPMN |
| --- | --- |
| Разграничение доступа | `managerDecision` назначена группе `MANAGER`; сервисный слой дополнительно проверяет роль менеджера |
| Транзакции | Делегаты одобрения и отклонения вызывают существующие транзакционные сервисы |
| Асинхронная обработка | `publishApplicationCreated` отмечена `camunda:asyncBefore="true"` и публикует Kafka-событие |
| Периодические задачи | Граничный таймер запускает существующую логику уведомления менеджеров |
| Внешний адаптер | Интеграция с Taiga остаётся за JCA-адаптером и вызывается из делегатов процесса |
| Пользовательские формы | Стартовая задача и задача менеджера используют JSON-формы Camunda |
